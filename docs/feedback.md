# 反馈有效性与 JointState 时间戳

节点通过 `SDK.get_feedback()` 读取本地不可变反馈，不发送查询、不计算正运动学。
A7、A7lite、P7 及 CANTransport/dispatcher 使用相同的新鲜度判定。原来的 SDK 数组读取接口
仍可使用，但这些接口不提供失效判断，节点不再使用它们组成状态消息。

## 何时发布

`config/arm_config.yaml` 中设置 `feedback_timeout: 0.5`（秒，有限正数）。两个 launch 均转发该参数。
每次发布前检查七个关节的位置、速度、力矩；存在以下任一情况时，本周期不发布 JointState：

- SDK 已关闭或报告 CAN 故障。
- 任一字段缺失、非有限数值、来自未来，或主机接收年龄超过 `feedback_timeout`。
- 节点尚未建立当前 ROS 时钟周期内的反馈时间映射。

节点在状态变化时记录暂停原因，完整新反馈到达后记录恢复。不会用零值、NaN 消息或当前时间
填补失效数据。数采方应把话题中断视为数据不可用，不能无限保留上一条消息作为当前观测。
这项修复限定状态发布；不会因反馈过期额外发送使能、失能或运动命令。

超时使用主机 `time.monotonic()`，系统时间调整和 ROS 仿真时间暂停不会改变样本的真实年龄。
阈值应大于最慢字段的轮询/心跳周期及正常调度余量；A7 默认力矩轮询 50 ms，P7 末两电机心跳
200 ms。如果自定义更慢的反馈周期，应同步调整阈值。0.5 秒不是实时性能承诺。

## header.stamp 的含义

一个 JointState 可能包含不同接收时刻的缓存，尤其 A7 的位置、速度、力矩分别轮询。
节点使用**所有关节、所有发布字段中最老的主机接收时刻**，并取不晚于它的最近一次 ROS
时钟观测作为 `header.stamp`。该时间比最老接收时刻保守，正常运行时额外向前取整误差不超过
相邻发布回调的间隔；回调被调度阻塞时误差也会增加。它不是严格同步采样时刻。

- 重复读取同一缓存保留相同时间戳，不在 100 Hz 发布时虚构 100 Hz 新观测。
- 某个字段尚未更新时，即使角度继续变化，整条消息的时间戳也可能保持不变。
- 启动后等待所有字段在首个时钟观测后更新；不会把初始化期间缓存直接标为当前观测。
- 使用 `use_sim_time` 时采用实际观察到的 `/clock` 值，不把主机秒数直接减到仿真时间上。
  暂停的仿真时钟产生相同时间戳；主机年龄仍会过期。ROS 定时器本身暂停时也不会继续发布。
- 相邻回调检测到 ROS 时钟倒退、时钟模式切换，或系统时钟与单调时钟增量相差超过 100 ms
  时，清空映射，等待每个字段在新周期内更新。仿真时钟大步前进时保留此前映射，旧样本继续
  使用前进之前的时间戳，新接收的数据才映射到后续时钟；正常的低频或加速时钟不会因此饿死发布。
  这是发布回调观察到的时钟变化，不是对两个回调之间所有 `/clock` 跳变的完整追踪。

SDK 时间记录于主机电机解码回调，不是嵌入式采样时间。适配器/驱动缓冲、主机调度或固件处理
在解码前造成的延迟不能据此识别；同地址协议没有事务序号时，迟到回复也有不可消除的边界。
需要严格跨设备采样同步时，数采系统还需单独定义硬件采样与对时方案。

## 关闭与恢复

仅反馈暂停、SDK 未关闭：全部字段恢复有效后自动恢复状态发布。
SDK 已关闭或发生总线故障：旧缓存持续无效，按原生命周期规则重建 SDK/重启节点；不会自动
重新使能或恢复运动。源码依赖及旧 SDK 能力检查见 [环境配置](environment_setup.md)。
