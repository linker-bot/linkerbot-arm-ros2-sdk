# 反馈有效性与时间戳

节点读取 SDK 的不可变 `get_feedback()` 本地快照，不发送查询、不计算正运动学。七个关节的位置、速度、力矩均有效且新鲜时才发布 JointState。

## 暂停与恢复

以下任一情况会暂停本周期状态发布：

- SDK 已关闭或报告 CAN 故障。
- 任一字段缺失、NaN/Inf、接收时间来自未来，或接收年龄超过 `feedback_timeout`。
- 尚未建立当前 ROS 时钟周期内的反馈时间映射。

节点在状态变化时记录暂停原因，完整反馈恢复后记录恢复。不用零值、NaN 消息或当前时间补齐缺失数据。订阅方应把话题中断视为数据不可用，不能一直把上一条消息当作当前状态。

反馈超时使用主机单调时钟，不受系统时间调整或 ROS 仿真时钟暂停影响。默认阈值 0.5 秒，应大于最慢字段的轮询/心跳周期与调度余量；例如 A7 默认力矩轮询 50 ms，P7 末两电机心跳 200 ms。

反馈暂停本身**不会额外发送停止或失能命令**。需要基于反馈丢失停止的应用，须另行实现并调用[生命周期服务](services.md)。SDK 关闭或总线故障后按生命周期规则重建连接/重启节点，不自动恢复运动。

## `header.stamp` 表示什么

一条消息可能包含不同时间收到的字段。节点以全部关节、全部发布字段中**最老的主机接收时刻**为基准，使用不晚于它的最近 ROS 时钟观测作为时间戳。

- 相同缓存保留相同时间戳；100 Hz 发布不等于 100 Hz 新测量。
- 正常情况下，向前取整误差不超过相邻发布回调间隔；调度阻塞会增加误差。
- 启动时等待全部字段在首个时钟观测之后更新，不把初始化缓存标成当前数据。

SDK 保留 transport 接收/分发入口传递的原始主机接收时间，不把排队后解码的时间当成新反馈。它仍不是嵌入式采样时间，无法判断记录时间点之前的固件或驱动缓冲延迟。

## 仿真时钟与跳变

使用 `use_sim_time` 时，时间戳使用实际观察到的 `/clock`，不将主机年龄直接从仿真时间中扣除。仿真时间暂停时可保留相同时间戳，主机年龄仍会过期；ROS 定时器暂停时也不会继续发布。

发布回调观察到 ROS 时间倒退、时钟模式切换，或系统时间增量与单调时间增量相差超过 100 ms 时，清空时间映射并等待所有字段重新更新。仿真时间向前跳变时保留旧映射，旧样本保留跳变前时间戳。两个回调之间未观察到的跳变不能完整追踪。

这些时间戳用于保守表达数据年龄，不提供跨设备同步采样保证。
